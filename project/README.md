# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект должен демонстрировать применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и (по возможности) воспроизводимость.

## 1. Паспорт проекта

- **Название проекта:** `AI Moderator Bot — интеллектуальная система автоматической модерации сообщений для мессенджеров`
- **Автор:** `Филимонов Владимир Николаевич`

- **Контакт:** [t.me/Limon4egtop](https://t.me/Limon4egtop), limon4egtop@vk.com

- **Краткое описание:**  
Проект представляет собой интеллектуальную систему автоматической модерации сообщений в групповых беседах. Основой решения является нейросетевая модель, предназначенная для анализа текстовых сообщений пользователей и выявления нарушений правил общения, включая спам, рекламу, токсичность, нецензурную лексику и иные нежелательные формы контента.
В качестве демонстрационного интерфейса используется Telegram-бот, однако архитектура проекта предусматривает возможность интеграции с любыми мессенджерами и коммуникационными платформами через API. При обнаружении нарушений модель передаёт сервису модерации команду на выполнение соответствующего действия: удаление сообщения, временное ограничение пользователя, предупреждение или автоматическую блокировку.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
  - при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

Если структура проекта отличается от базовой, опишите это здесь.

## 6. Тесты

В проекте реализован набор автоматических тестов для проверки основных компонентов системы интеллектуальной модерации сообщений.

Добавлены следующие типы тестов:

- модульные тесты загрузки датасета;
- модульные тесты предварительной обработки текста;
- sanity-check тесты модели машинного обучения;
- тесты класса предсказания `MessageClassifier`;
- базовые e2e-тесты API-сервиса FastAPI.

Тесты загрузки данных проверяют наличие файла датасета, обязательных колонок `text` и `label`, отсутствие пустых сообщений и наличие трёх целевых классов: `normal`, `spam`, `profanity`.

Тесты preprocessing-модуля проверяют нормализацию текста: приведение к нижнему регистру, замену буквы `ё`, удаление лишних пробелов и обработку ссылок.

Тесты модели проверяют, что baseline-модель на основе TF-IDF и Logistic Regression может обучаться на небольшом наборе сообщений, выполнять многоклассовую классификацию и возвращать вероятности по классам.

Тесты предсказания проверяют структуру ответа классификатора: наличие метки класса, уверенности модели, признака нарушения, рекомендованного действия и вероятностей по каждому классу.

API-тесты проверяют работоспособность эндпоинтов `/health` и `/predict`.

Для запуска тестов используется `pytest`. Команда запуска из корня репозитория:

```bash
uv run pytest project/tests
```

Если запуск выполняется непосредственно из папки `project`, можно использовать команду:

```bash
uv run pytest tests
```

Перед запуском тестов, связанных с предсказанием и API, необходимо обучить модель:

```bash
uv run python -m src.train
```

После обучения файл модели сохраняется в директорию:

```text
artifacts/models/message_classifier.joblib
```
