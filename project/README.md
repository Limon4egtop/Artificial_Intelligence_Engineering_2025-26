# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект должен демонстрировать применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и (по возможности) воспроизводимость.

---

## 1. Паспорт проекта

- **Название проекта:** `AI Moderator Bot — интеллектуальная система автоматической модерации сообщений для мессенджеров`
- **Автор:** `Филимонов Владимир Николаевич`
- **Группа:** `<Группа ЭФБО-03-23`
- **Контакт:** [t.me/Limon4egtop](https://t.me/Limon4egtop), limon4egtop@vk.com

- **Краткое описание:**

Проект представляет собой интеллектуальную систему автоматической модерации сообщений в групповых чатах и сообществах.

Основой решения является ML-модель, предназначенная для анализа текстовых сообщений пользователей и выявления нарушений правил общения, включая:

- спам;
- рекламу;
- токсичность;
- нецензурную лексику;
- иные формы нежелательного контента.

В качестве демонстрационного интерфейса используется Telegram-бот, реализованный на библиотеке `aiogram 3`, однако архитектура проекта предусматривает возможность интеграции с любыми мессенджерами и коммуникационными платформами через API.

При обнаружении нарушений система автоматически:

- ограничивает пользователя;
- удаляет сообщение;
- отправляет уведомление в чат модераторов;
- предоставляет интерфейс ручной модерации.

## 4. Как запустить проект

### 4.1. Обучение модели

Перейдите в папку проекта:
```
cd project
uv sync
cd ..
```

Запуск обучения:

```bash
uv run python -m project.src.train
```

После обучения модель будет сохранена в:

```text
project/artifacts/models/message_classifier.joblib
```

Также будут сохранены:

```text
project/artifacts/metrics/classification_report.txt
project/artifacts/metrics/confusion_matrix.csv
```

---

### 4.2. Запуск API-сервиса

Проект содержит FastAPI-сервис для проверки сообщений через HTTP API.

Запуск:

```bash
uv run uvicorn project.src.service:app --reload
```

Сервис запускается на:

```text
http://127.0.0.1:8000
```

Swagger UI:

```text
http://127.0.0.1:8000/docs
```

---

### 4.3. Основные API-эндпоинты

#### Проверка состояния сервиса

```http
GET /health
```

Пример ответа:

```json
{
  "status": "ok"
}
```

---

#### Проверка сообщения

```http
POST /predict
```

Пример запроса:

```json
{
  "text": "Заработок от 5000 рублей в день без опыта"
}
```

Пример ответа:

```json
{
  "label": "spam",
  "confidence": 0.98,
  "recommended_action": "delete_message"
}
```

---

### 4.4. Запуск Telegram-бота

Перед запуском необходимо:

1. Создать Telegram-бота через BotFather;
2. Отключить Privacy Mode;
3. Добавить бота в чат;
4. Выдать полные права администратора

Запуск:

```bash
uv run python -m project.src.bot.telegram_bot
```

После запуска бот начинает автоматически модерировать сообщения в чатах, указанных в `.env`.

## 6. Тесты

В проекте реализован набор автоматических тестов для проверки основных компонентов системы интеллектуальной модерации сообщений.

Добавлены следующие типы тестов:

- модульные тесты загрузки датасета;
- модульные тесты предварительной обработки текста;
- sanity-check тесты модели машинного обучения;
- тесты класса предсказания `MessageClassifier`;
- базовые e2e-тесты API-сервиса FastAPI.

Тесты загрузки данных проверяют наличие файла датасета, обязательных колонок `text` и `label`, отсутствие пустых сообщений и наличие трёх целевых классов: `normal`, `spam`, `profanity`.

Тесты preprocessing-модуля проверяют нормализацию текста: приведение к нижнему регистру, замену буквы `ё`, удаление лишних пробелов и обработку ссылок.

Тесты модели проверяют, что baseline-модель на основе TF-IDF и Logistic Regression может обучаться на небольшом наборе сообщений, выполнять многоклассовую классификацию и возвращать вероятности по классам.

Тесты предсказания проверяют структуру ответа классификатора: наличие метки класса, уверенности модели, признака нарушения, рекомендованного действия и вероятностей по каждому классу.

API-тесты проверяют работоспособность эндпоинтов `/health` и `/predict`.

Для запуска тестов используется `pytest`. Команда запуска из корня репозитория:

```bash
uv run pytest project/tests
```

Если запуск выполняется непосредственно из папки `project`, можно использовать команду:

```bash
uv run pytest tests
```

Перед запуском тестов, связанных с предсказанием и API, необходимо обучить модель:

```bash
uv run python -m src.train
```

После обучения файл модели сохраняется в директорию:

```text
artifacts/models/message_classifier.joblib
```

## 8. Ограничения и дальнейшая работа

Текущая версия проекта имеет ряд ограничений:

- отсутствует полноценная нейросетевая архитектура;
- отсутствует хранение кейсов модерации в базе данных;
- используется in-memory storage;
- отсутствует поддержка мультиязычности;
- модель работает только с текстом.

Проект может быть расширен в следующих направлениях:

- поддержка мультиязычной модерации;
- подключение PostgreSQL;
- интеграция Redis;
- веб-панель модераторов;
- интеграция с Discord, VK и Slack;
- дообучение модели на пользовательских данных;
- поддержка анализа изображений и медиа.
